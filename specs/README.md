# Разработка по спецификациям

Для этого проекта SDD ведётся в Markdown внутри репозитория.
Дополнительные зависимости или плагины Xcode не нужны.

## Рабочий цикл

1. Прочитать [контекст продукта](../docs/product-context.md) и существующую спецификацию.
2. Для новой функции скопировать [шаблон](feature-template.md) в `specs/NNN-feature-name.md`.
3. Записать цель, сценарии, критерии приёмки, ограничения и открытые вопросы.
   Указать источники требований и отдельно — собственные решения для прототипа.
4. Составить короткий план изменений и проверок; реализовать код по этому плану.
5. Проверить критерии приёмки. Записать фактические результаты, непроверенные
   сценарии и ограничения среды. Обновить спецификацию при изменении поведения.

Пример задания для Codex:

> Добавь экран содержимого пространства. Сначала создай его спецификацию
> по шаблону specs/feature-template.md с учётом контекста продукта,
> затем реализуй интерфейс на демонстрационных данных и проверь критерии приёмки.

Не требуется отдельное согласование каждого документа: двигайтесь в рамках
задания пользователя, отмечая допущения и уточняя блокирующие вопросы.

## Карта экранов

| Экран | Спецификация | Состояние |
| --- | --- | --- |
| 1. Список чатов и пространств | [002-space-main.md](002-space-main.md) | Последняя редакция внесена в код; 18 тестов модели/маршрутов прошли. Сборка и визуальная приёмка iOS не выполнены |
| 2. Пространство | [space-space.md](space-space.md) | Новая спецификация: рабочая область сверху, общая личная пятёрка снизу, особенная шапка; в коде пока пустой экран |
| 3. Диалог чата/канала внутри пространства | Ожидает отдельной спецификации пользователя | Прямой маршрут к выбранному диалогу, пустой экран с общей шапкой; содержимое ожидается |
| 4. Активности | [space-activity.md](space-activity.md) | Новая спецификация четырёх раскрывающихся групп и сквозного входа, включая треды; в коде пока пустой каркас |

Общее ограничение: четыре экрана, без бэкенд-логики. Наличие документа
не означает, что функция реализована или проверена.

Отдельный экран «Активности» описан в `space-activity.md`, главная внутри
пространства — в `space-space.md`; эти имена заданы пользователем.
Нумерация в карте — порядок описания экранов,
а не обязательная последовательность переходов. В спецификации главной заданы
разные переходы в пространство и сразу в диалог, изменение заголовка на название
пространства и сквозная кнопка активностей без видимой текстовой подписи.
Переходы и общие шапки реализованы как пустые экраны назначения.
Содержимое пространства и активностей теперь описано, но пока не реализовано.
Диалог и его режим треда ожидают отдельной спецификации.

[001-chat-list.md](001-chat-list.md) сохраняет описание исходного прототипа.
Файл `002-space-main.md` по запросу пользователя содержит новую редакцию
первого экрана, а не описание второго.
